==🟡1.epoll 有两种触发模式：==

- **LT（水平触发）**：只要缓冲区还有数据未读取，就可以持续通知你。
    
- **ET（边缘触发）**：只有数据状态发生变化时才通知，例如从无数据变为有数据。
    

假设 Socket 缓冲区有 10KB 数据，你每次只读取 1KB：

- LT：剩余 9KB 时，仍然可以再次通知。
    
- ET：可能不会再次通知，因为缓冲区一直处于可读状态，没有发生新的边缘变化。
    

所以 ET 通常需要配合非阻塞 I/O，循环读取直到返回 `EAGAIN`。

**额外记忆：** ET 不等于异步 I/O。epoll 本身属于 I/O 多路复用机制。


==🔴2.Java 只有值传递（Pass by Value），对象参数传递的是**引用的副本**，不是对象本身。==

这里要区分两种操作：

**1. 修改对象内部属性**

```
static void change(Person p) {
    p.name = "Bob";
}
```

方法内外的引用都指向同一个对象，因此调用后原对象的属性也会改变。

**2. 重新给参数赋值**

```
static void change(Person p) {
    p = new Person("Charlie");
}
```

这里只修改了局部引用副本的指向，不会改变调用方的引用。

这也是 Java 面试中非常经典的考点。与你上传的 Java 面试资料中的「值传递和引用传递的区别」一致。

==🔴4.这道题考察的是 Java 的**静态方法隐藏（Method Hiding）和实例方法重写（Method Overriding）**。==

class Parent {
    static void m() {
        System.out.print("P");
    }

    void n() {
        System.out.print("p");
    }
}

class Child extends Parent {
    static void m() {
        System.out.print("C");
    }

    @Override
    void n() {
        System.out.print("c");
    }
}

public class Main {
    public static void main(String[] args) {
        Parent obj = new Child();
        obj.m();
        obj.n();
    }
}

A. `Pc`

B. `PC`

C. `Cc`

D. `Cp`

**请选择一个答案，并解释为什么两个方法的调用结果可能不同**

关键区别在于：

**1. 静态方法：编译时确定**

```
Parent obj = new Child();
obj.m();
```

`m()` 是静态方法，调用哪个方法取决于引用变量的声明类型 `Parent`，所以调用 `Parent.m()`，输出 `P`。

子类定义同名静态方法属于方法隐藏，不是多态意义上的重写。

**2. 实例方法：运行时确定**

```
obj.n();
```

`n()` 是实例方法，遵循动态绑定。虽然引用类型是 `Parent`，但实际对象是 `Child`，所以调用 `Child.n()`，输出 `c`。

记住一句话：**静态方法看引用类型，实例方法看实际对象类型。**


### ==🔴5.**图的 BFS（单选）**==

对于一个无权无向图，要求求出起点到所有其他节点的最短路径长度，以下说法正确的是？

A. 使用 DFS 即可保证第一次访问节点时得到最短路径。

B. 使用 BFS，并在节点入队时标记 visited，可以在 \(O(V+E)\) 时间内完成遍历。

C. 必须使用 Dijkstra 算法，BFS 无法求最短路径。

D. BFS 的时间复杂度一定是 \(O(V^2)\)。

**请选择一个答案，并说明为什么 BFS 能求无权图的最短路径。**

BFS（广度优先搜索）能够求无权图最短路径，是因为它按照距离起点的层数逐层扩展。

例如：

```
       A
      / \
     B   C
    /     \
   D       E
    \     /
       F
```

从 A 开始：

- 第 0 层：A
    
- 第 1 层：B、C
    
- 第 2 层：D、E
    
- 第 3 层：F
    

BFS 保证先访问距离近的节点，再访问距离远的节点，因此第一次访问某个节点时，就已经得到它的最短路径长度。

**一个重要细节：** 应该在节点入队时标记 `visited`，而不是出队时。这样可以避免同一个节点被多个相邻节点重复加入队列。

使用邻接表时，时间复杂度为：

\[ O(V+E) \]


### ==🔴**6.Spring 事务（多选题，4 分）**==

关于 Spring 的 `@Transactional`，下列说法正确的是？

A. 默认情况下，抛出 `RuntimeException` 或 `Error` 会触发事务回滚。

B. 默认情况下，抛出普通的受检异常也一定会触发事务回滚。

C. 在默认代理模式下，同一个类内部通过 `this.xxx()` 调用另一个事务方法，通常不会经过事务代理。

D. 只要添加了 `@Transactional`，无论是否经过 Spring 代理，都能保证事务生效。

**请选择所有正确选项，并说明理由。**

你选了 B、C，实际上正确答案是 **A、C**。

逐项分析：

- **A 正确**：默认情况下，Spring 遇到 `RuntimeException` 或 `Error` 会触发事务回滚。
    
- **B 错误**：普通受检异常（例如 `IOException`）默认不会触发回滚。可以通过 `rollbackFor = Exception.class` 指定回滚规则。
    
- **C 正确**：Spring 默认使用代理模式管理事务。同一个类内部通过 `this.xxx()` 调用，不会经过代理对象，因此通常不会触发被调用方法上的事务增强。
    
- **D 错误**：`@Transactional` 不是魔法注解，必须满足代理生效等条件。
    

这里建议你重点记住两个知识点：**Spring 默认回滚规则，以及 AOP 代理机制导致的事务自调用失效。**

### **8.Redis ZSet 与分布式锁（多选题，4 分）**

关于 Redis，下列说法正确的是？

A. ZSet 中的 member 具有唯一性。

B. ZSet 按 score 排序，score 相同时还会按照 member 的字典序排序。

C. Redis 中所有 ZSet 都一定使用跳表和哈希表实现。

D. Redis 分布式锁释放时，应当通过原子操作比较锁的持有者标识，再删除锁。

E. 使用 `SET key token NX PX 30000` 可以完成一次原子加锁尝试，并设置过期时间。

F. Redisson 看门狗机制可以在持有者仍正常持有锁时续期，避免锁因固定租期过期而意外释放。

逐项分析：

- **A 正确**：ZSet 的 member 唯一，相同 member 再次添加时会更新 score，而不是新增元素。
    
- **B 正确**：先按照 score 排序；score 相同时，按照 member 的字典序排序。
    
- **C 错误**：ZSet 并不一定使用跳表和哈希表。小数据量时可以使用 listpack；较大数据量时使用跳表和哈希表。
    
- **D 正确**：释放锁时必须比较持有者标识，并且比较和删除必须是原子操作，通常使用 Lua 脚本。
    
- **E 正确**：`SET key token NX PX 30000` 一条命令完成加锁和设置过期时间。
    
- **F 正确**：Redisson 看门狗会定期续期，避免业务尚未执行完毕，锁就因为租约到期而被释放。默认看门狗超时时间通常是 30 秒，显式指定 leaseTime 时则不会采用默认看门狗续期机制。
    

这里特别提醒：**Redis 分布式锁最容易考的是为什么不能直接 DEL 解锁。** 因为锁可能已经过期并被其他客户端重新获取，旧客户端直接删除就会误删别人的锁。

==🟡1.epoll 有两种触发模式：==

- **LT（水平触发）**：只要缓冲区还有数据未读取，就可以持续通知你。
    
- **ET（边缘触发）**：只有数据状态发生变化时才通知，例如从无数据变为有数据。
    

假设 Socket 缓冲区有 10KB 数据，你每次只读取 1KB：

- LT：剩余 9KB 时，仍然可以再次通知。
    
- ET：可能不会再次通知，因为缓冲区一直处于可读状态，没有发生新的边缘变化。
    

所以 ET 通常需要配合非阻塞 I/O，循环读取直到返回 `EAGAIN`。

**额外记忆：** ET 不等于异步 I/O。epoll 本身属于 I/O 多路复用机制。


==🔴2.Java 只有值传递（Pass by Value），对象参数传递的是**引用的副本**，不是对象本身。==

这里要区分两种操作：

**1. 修改对象内部属性**

```

    p.name = "Bob";
```

方法内外的引用都指向同一个对象，因此调用后原对象的属性也会改变。

**2. 重新给参数赋值**

```

    p = new Person("Charlie");
```

这里只修改了局部引用副本的指向，不会改变调用方的引用。

```
    }
```

    }

        obj.n();
    }
}

A. `Pc`

B. `PC`

C. `Cc`

D. `Cp`

```
obj.m();
```

`m()` 是静态方法，调用哪个方法取决于引用变量的声明类型 `Parent`，所以调用 `Parent.m()`，输出 `P`。

**2. 实例方法：运行时确定**

对于一个无权无向图，要求求出起点到所有其他节点的最短路径长度，以下说法正确的是？

A. 使用 DFS 即可保证第一次访问节点时得到最短路径。

B. 使用 BFS，并在节点入队时标记 visited，可以在 \(O(V+E)\) 时间内完成遍历。

C. 必须使用 Dijkstra 算法，BFS 无法求最短路径。

D. BFS 的时间复杂度一定是 \(O(V^2)\)。

**请选择一个答案，并说明为什么 BFS 能求无权图的最短路径。**

BFS（广度优先搜索）能够求无权图最短路径，是因为它按照距离起点的层数逐层扩展。

例如：

```
       A
      / \
     B   C
    /     \
   D       E
    \     /
       F
```

从 A 开始：

- 第 0 层：A
    
- 第 1 层：B、C
    
- 第 2 层：D、E
    
- 第 3 层：F
    

BFS 保证先访问距离近的节点，再访问距离远的节点，因此第一次访问某个节点时，就已经得到它的最短路径长度。

**一个重要细节：** 应该在节点入队时标记 `visited`，而不是出队时。这样可以避免同一个节点被多个相邻节点重复加入队列。

### ==🔴**11.Spring 事务传播机制（多选，4 分）**==

假设有以下两个 Service：

```
@Service
public class OrderService {

    @Transactional
    public void createOrder() {
        orderMapper.insert();

        try {
            paymentService.pay();
        } catch (Exception e) {
            System.out.println("支付失败");
        }
    }
}

@Service
public class PaymentService {

    @Transactional(propagation = Propagation.REQUIRED)
    public void pay() {
        paymentMapper.insert();
        throw new RuntimeException("支付失败");
    }
}
```

关于这段代码，下列说法正确的是？

A. `REQUIRED` 表示如果当前存在事务，则加入当前事务；否则创建新事务。

B. `pay()` 抛出 RuntimeException 后，整个订单事务一定会回滚，即使异常被 `createOrder()` 捕获。

C. 如果 `pay()` 使用 `REQUIRES_NEW`，那么它会挂起外层事务，创建一个新的独立事务。

D. 如果 `pay()` 使用 `NESTED`，那么它一定会创建一个完全独立的物理事务。

E. 如果 `pay()` 使用 `REQUIRES_NEW`，即使支付事务回滚，也不一定影响外层订单事务的提交。

**请选择所有正确选项，并说明理由。**

这道题的关键是理解：**内部事务方法抛出异常后，即使外部方法捕获异常，也不代表事务可以正常提交。**

逐项分析：

- **A 正确**：`REQUIRED` 是默认传播行为。有事务就加入，没有事务就创建。
    
- **B 正确**：这是本题最重要的考点。`pay()` 通过 Spring 代理执行，抛出 `RuntimeException` 后，事务拦截器会将当前共享事务标记为 `rollback-only`。即使外层 catch 住异常，也无法取消这个标记。外层提交时最终会回滚，并可能抛出 `UnexpectedRollbackException`。
    
- **C 正确**：`REQUIRES_NEW` 会挂起外层事务，创建一个独立的物理事务。
    
- **D 错误**：`NESTED` 通常基于数据库 Savepoint（保存点）实现，属于同一个物理事务，并不是独立物理事务。
    
- **E 正确**：内部 `REQUIRES_NEW` 事务回滚，不代表外部事务也必须回滚。只要外层没有其他回滚原因，仍然可以提交。
    

### **重点记忆：三种传播机制**

| ==🔴传播机制==         | ==🔴有外层事务时==                 | ==🔴事务关系==    |
| ------------ | ---------------------- | ------- |
| ==🔴REQUIRED==     | ==🔴加入外层事务==                 | ==🔴共享物理事务==  |
| ==🔴REQUIRES_NEW== | ==🔴挂起外层，创建新事务==             | ==🔴独立物理事务==  |
| ==🔴NESTED==       | ==🔴创建嵌套事务（通常使用 Savepoint）== | ==🔴同一个物理事务== |

尤其注意：`REQUIRED` 的内部方法发生默认规则下的运行时异常，即使被外部捕获，也可能导致整个事务回滚。

### **3. 面试最容易追问的三个问题**

**问题一：为什么 WHERE 不能使用 SELECT 中定义的别名？**

例如：

```
SELECT salary * 12 AS annual_salary
FROM employees
WHERE annual_salary > 100000;
```

这条 SQL 在 MySQL 中会报错。

原因是 WHERE 的逻辑执行顺序在 SELECT 之前。

执行 WHERE 时，SELECT 中定义的 `annual_salary` 别名还没有产生。

但 ORDER BY 可以使用这个别名，因为 ORDER BY 在 SELECT 之后执行。

**问题二：WHERE 和 HAVING 有什么区别？**

|对比|WHERE|HAVING|
|---|---|---|
|执行时机|GROUP BY 之前|GROUP BY 之后|
|过滤对象|原始数据行|分组后的数据|
|能否使用聚合函数|不能直接使用|可以|
|是否可以单独使用|可以|可以（不依赖 GROUP BY 时作为结果过滤）|

简单理解：

- WHERE：先过滤数据，再分组。
    
- HAVING：先分组，再过滤分组。
    

**问题三：LEFT JOIN 中 ON 和 WHERE 有什么区别？**

这是非常容易考的地方。

```
SELECT *
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.id
AND d.name = '技术部';
```

这里即使员工不属于技术部，也会保留员工记录，只不过右表对应字段为 NULL。

如果改成：

```
SELECT *
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.id
WHERE d.name = '技术部';
```

那么不属于技术部的员工会被 WHERE 过滤掉，实际上会使 LEFT JOIN 的结果表现得类似 INNER JOIN。

**面试时可以这样回答：**

SQL 查询的逻辑执行顺序是 FROM → ON → JOIN → WHERE → GROUP BY → 聚合函数 → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。

其中最需要注意的是 WHERE 在 GROUP BY 之前，用于过滤原始数据；HAVING 在 GROUP BY 之后，用于过滤分组结果。另外，由于 SELECT 在 WHERE 之后执行，所以 WHERE 不能使用 SELECT 中定义的别名，但 ORDER BY 可以。

**核心记忆点：WHERE 过滤行，HAVING 过滤组，SELECT 选择列，ORDER BY 排序，LIMIT 限制结果数量。**

- **F 错误**：全连接队列满了会影响新连接建立，服务端可能无法正常接收已完成握手的连接。

**第一次握手：** 服务端收到 SYN，进入 SYN_RECV，半连接队列。

**第二次握手：** 服务端发送 SYN+ACK，等待客户端确认。

**第三次握手：** 服务端收到 ACK，连接进入 ESTABLISHED，等待 accept()。

注意：这里描述的是 Linux 典型 TCP 监听套接字的队列模型。

### ==🟠**Java NIO 与 Linux Epoll（多选，4 分）**==

关于 Java NIO、Epoll 和 Reactor 模型，下列说法正确的是？

A. Java NIO 的 Selector 可以同时监听多个 Channel 的 I/O 事件。

B. Epoll 采用主动轮询所有 Socket 的方式检查是否有 I/O 事件。

C. Reactor 模型的核心思想是将 I/O 事件分发给对应的处理器。

D. NIO 中的 Buffer 负责数据存储，Channel 负责数据传输，Selector 负责监听多个 Channel 的事件。

E. Epoll 的 ET（边缘触发）模式下，如果一次没有读取完缓冲区中的数据，后续一定会再次通知可读事件。

F. Java NIO 一定意味着底层使用 Epoll，Windows 和其他操作系统也都是如此。

**请选择所有正确选项，并解释 Selector、Channel、Buffer 三者的关系。**

正确答案：**A、C、D**。你漏选了 C，没有选错选项。

逐项分析：

- **A 正确**：Selector 可以同时监听多个 Channel 的 I/O 事件。
    
- **B 错误**：Epoll 不是主动轮询所有 Socket，而是采用事件驱动机制，内核维护就绪事件链表，只返回发生事件的 Socket。
    
- **C 正确**：Reactor 模型的核心是事件分发，将 I/O 就绪事件交给对应的处理器处理。
    
- **D 正确**：Java NIO 三大核心组件就是 Channel、Buffer、Selector。
    
- **E 错误**：ET（边缘触发）模式下，同一个就绪事件通常只通知一次，因此需要尽可能读取完内核缓冲区的数据，通常循环读取直到返回 EAGAIN。
    
- **F 错误**：Java NIO 是跨平台 API，底层多路复用机制取决于操作系统。Linux 可以使用 Epoll，不能认为所有系统都使用 Epoll。
    

### **重点：NIO 三大组件的关系**

例如客户端发送数据时，Selector 监听 Channel 是否可读；当数据就绪，程序从 Channel 读取数据到 Buffer，再进行业务处理。

Reactor 模型则负责把这些就绪事件分发给对应的处理器。Netty 就是典型的应用。
